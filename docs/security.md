# Security

## Identity and least privilege

| Principal | Can | Cannot |
|---|---|---|
| DMS S3 role | Put objects under `raw/cdc/*` | Read anything; touch processed |
| DMS secrets role | Read the DMS source secret only | Other secrets |
| Glue transform role | Read `raw/cdc/*` and run manifests; write `validated/`, `deduplicated/`, `rejected/`, `audit/` | Read GCP credentials |
| Glue transfer role | Read `deduplicated/*` and `audit/*`; write `audit/*`; read the GCP credential secret | Read raw, validated or rejected data |
| Airflow role | Start and poll the two Glue jobs; list buckets; read/write `control/` and `audit/` | Write data zones |
| GCP `gcs-writer` SA (via WIF from the transfer role only) | Create and view objects in the staging bucket | BigQuery |
| GCP `bq-loader` SA | BigQuery job user (project); data editor on the three CDC datasets only; read staging bucket | Other datasets; write GCS |

The WIF provider has an `attribute_condition` that admits only the pipeline's AWS roles. The
service-account binding is scoped to the exact assumed-role ARN.

## Secrets

* RDS admin password: generated and rotated by RDS (`manage_master_user_password`); never in
  Terraform state.
* DMS user password: generated by `bootstrap_aws.sh` straight into Secrets Manager (KMS CMK);
  never in state or on disk.
* GCP: a **Workload Identity Federation credential configuration** (not a secret) in Secrets
  Manager. The service-account-key fallback is documented, but avoid it. If you must use it,
  rotate every 90 days and restrict it with org policy `iam.disableServiceAccountKeyCreation`
  exceptions.
* Nothing secret lives in the repo. `.env`, `*.tfvars` and credential files are git-ignored.
  `.env.example` and the tfvars examples hold placeholders only.

## Encryption

* S3 raw, processed and artifacts: SSE-KMS with a pipeline CMK (rotation on) and S3 Bucket
  Keys. Access-log bucket: SSE-S3 (log delivery requirement). TLS-only bucket policies, Block
  Public Access, BucketOwnerEnforced.
* RDS storage, Performance Insights, DMS instance, Glue (S3, CloudWatch, bookmarks), CloudWatch
  log groups and Secrets: KMS.
* GCS and BigQuery: Google-managed encryption by default. Use CMEK if policy requires it
  (`encryption` block / `default_encryption_configuration`).
* In transit: TLS everywhere (`rds.force_ssl=1`, DMS `ssl_mode=require`, HTTPS to GCS and
  BigQuery).

## Network paths

```
RDS (private subnet, SG: 5432 from DMS SG only)
  ▲
DMS (private subnet, SG egress: 5432 to RDS, 443 to VPC endpoints)
  │ S3 gateway endpoint, Secrets Manager / KMS / Logs / Monitoring interface endpoints
  ▼
S3 raw ──► Glue (AWS-managed network) ──► S3 processed
                     │ HTTPS 443 → storage.googleapis.com, sts.googleapis.com (WIF)
                     ▼
                  GCS staging ──► BigQuery (Google network)
```

* No IGW or NAT in the VPC; RDS is not publicly accessible.
* Glue jobs need no VPC connection (S3 only, plus Google APIs over the internet). If your policy
  forces Glue into the VPC, add a NAT gateway or egress proxy allowing `*.googleapis.com:443`.
* `bootstrap_aws.sh` needs a path into the VPC (CloudShell VPC environment or an SSM bastion).
* Optional hardening: VPC Service Controls around the GCP project; an S3 bucket policy
  `aws:SourceVpce` for human access.

## Data protection and governance

* PII columns are flagged in `pipeline_config.yaml` (`pii: true`) and described as PII in
  BigQuery. Apply **BigQuery policy tags** (column-level security) and/or authorized views for
  analysts, and expose `WHERE NOT _is_deleted` views only.
* Rejected records keep the raw payload, PII included. They stay in AWS (never transferred),
  are KMS-encrypted and expire after 30 days.
* For GDPR erasure, use the hard-delete strategy for the affected tables and purge raw and
  processed copies within retention, or shorten retention.

## Data residency and egress

* The BigQuery location (`bq_location`) and GCS region are explicit variables. Choose them to
  meet residency requirements; data crosses jurisdictions only if you choose so.
* Only deduplicated curated data leaves AWS, and AWS bills it as internet egress (COST_NOTES).
* Record the cross-cloud flow in your data processing inventory (ROPA) and DPAs. Both providers
  act as processors.
